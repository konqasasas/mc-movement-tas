# approx: 近似探索エンジン

大きなコースで、短い計算時間のうちに速い解答を見つけるための探索です。最適性は保証しません。最適解を証明する探索(`search`、WS3)とは別の方針で作り、同じ問題集と同じ採点コマンドで比べます。

```
./gradlew :approx:installDist
approx/build/install/mctas-approx/bin/mctas-approx solve problems/v0 out/ --budget 15
approx/build/install/mctas-approx/bin/mctas-approx gen problems/v1-dev v1-dev 1 8
problem/build/install/mctas-problem/bin/mctas-problem score problems/v0 out/ --markdown
```

- `solve <問題|フォルダ> <出力フォルダ> [--budget 秒] [--quiet]`: 問題ごとに `--budget` 秒(既定 30)まで探し、`<id の / を _ に>.solution.json` と `.tas` を書きます。解答ファイルの `result.search` に `engine`(`approx-beam-v2` のように版を含む名前)と `wallMillis`(その問題にかけた全時間)が入ります。
- `gen <出力フォルダ> <セット名> <最初のシード> <個数> [--full]`: ランダムなジャンプコースを作ります。シード `s` のコースはジャンプ `5 + s % 8` 回です。`--full` を付けると足場はすべて石になります(フルブロックだけを扱う厳密な探索向け)。

## しくみ

1. **経路**(`Route`): ワールドの立てる面(上面とその上 1.8 ブロックの空き)を頂点にして、歩いて渡れる面と、全力のスプリントジャンプ(`JumpTable`、実測)で届く面を辺で結び、スポーンからゴールまでダイクストラで経路を引きます。高さの違う足場への乗り換えが「通過点」になります。ジャンプの到達距離には余裕(slack)を取れるので、余裕 0・0.5・1.0 の 3 本の経路を作り、同じものは除きます。攻めた経路は近道を通りますが、物理で届かないことがあります。
2. **手書きの方策**(`Pilot`): いつもスプリントして 45 度ずらして走り、届くならジャンプ、端から落ちる直前ならジャンプ(遅延ジャンプ)、空中では着地点の予測を通過点の内側 0.2 に寄せます。本物の物理で動かすので、ゴールまで行けばそれが正しい解答です。探索の最初に、各経路で方策だけを走らせて最初の解答を作り、行けた経路から順に探索します。
3. **ティック単位のビーム**(`TickBeam`): 助走の間はスタート直方体に入るまでを探し、入った時刻ごとに、入ってからの経過ティックで層を作ってビームを進めます。各ノードの順位付けは、安い見積もり(残り距離と着地予測)で候補を絞ってから、方策を 2 回の着地ぶん先まで物理で走らせて決めます(パイロット法)。今の最良より速くなりえないノードは捨てます。
4. **磨き込み**(`Refiner`): 解答が見つかるたびに、その前半を固定して残りを幅 1000 のビームで探し直します。区切りは、スタートに入る数ティック前(ジャンプと同じティックにスタートへ入る助走を探すため)と、各着地の 0・4・8 ティック前です。残り時間の 4 分の 1 までを使います。
5. **任意時間**(`ApproxSolver`): ビーム幅を 200、400、800… と倍にしながら、残り時間を経路どうしで分けて走らせます。どの解答も最後に判定と同じ規則(切り替えの 3 ティック規則を含む)で再計算して確かめます。

スプリントとスニークの切り替えは 3 ティック以上空けます(`ToggleRule`)。ダメージや畑の踏み荒らしは経路に入れません。
