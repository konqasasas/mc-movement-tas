# planner: 階層型プランナー

長い実コースの速い TAS を、近似探索(`approx`、ティック単位のビーム+磨き込み)とは違う考え方で探す探索です(D-500)。最適性は保証しません。同じ問題集と同じ採点コマンドで `approx` と比べます。

```
./gradlew :planner:installDist
planner/build/install/mctas-planner/bin/mctas-planner solve problems/v1-dev out/ --budget 30
problem/build/install/mctas-problem/bin/mctas-problem score problems/v1-dev out/ --markdown
```

- `solve <問題|フォルダ> <出力フォルダ> [--budget 秒] [--quiet] [--no-technique]`: 問題ごとに `--budget` 秒(既定 60)まで探し、`<id の / を _ に>.solution.json` と `.tas` を書きます。`result.search.engine` は `planner-v1`。`--no-technique` で WS8 の局所探索による区間の探し直しを切ります。
- 環境変数 `PLANNER_DEBUG=1` で、A* が一番ゴールに近づいたノードと、その後続がどこで捨てられたか(戻りすぎ、上限超え、既出・窓の外)を標準エラーに出します。`PLANNER_TRACE=1` で、はしご・つた・水の遷移が選んだ入口と出口を出します。

## しくみ(3 階層)

1. **足場グラフ**(`Course`): 立てるブロックの上面(上に 1.8 の空き)を足場にし、同じ高さで接する足場を 1 つの台にまとめます。歩けるか、全力のスプリントジャンプ(`Reach`、実測)に余裕 0.8 を足した距離で届く足場どうしを辺で結び、ゴールから逆向きのダイクストラで、各足場の中心からゴールまでの見積もり(最高速で中心から中心へ動いたときのティック数)を出します。これが A* の見積もりで、どの足場が前進かも決めます。マグマ、サボテン、炎、溶岩に触れる状態は捨てます(D-005)。
2. **速度状態の A***(`Planner`): ノードは「足場に着地した瞬間」の状態そのもの(物理の状態を丸ごと持つ)で、位置と水平速度を丸めたキーで同じ状態をまとめます。辺は区間遷移(`Maneuver`)で、今は自前の `StepManeuver` です。今いる台から出られる足場のうち見積もりの良いものを狙い、その足場の手前の点とレーシングライン上の点に向かって走り、地上の各ティックからジャンプする枝(届かないうちは即ジャンプと端でのジャンプだけ)と、跳ばずに別の台へ歩く・端から落ちる枝を、本物の物理で最後まで動かします。空中では、狙う足場の高さを落ちて通るティック(着地は横に動く前に決まる、L-013)の位置を予測し、足場の中に着地するように押す向きを決めます(足場を越えそうなときだけ引き戻し、それ以外は前へ押して速度を残す)。コストはスタートからのティック数。最初は見積もりの重み 3 で手早く 1 本見つけ、そのあとは最良タイムで枝を切りながら、重みを下げ、狙う足場を増やし、速度状態を細かくして、時間いっぱい探し直します。
3. **ティック単位のつなぎ直し**(`Tightener`): 計画は「狙う点・ジャンプのティック・横移動」の列として持っていて、どれかを変えると、その後ろは同じ制御で今の位置から再生し直せます。1 つずつ(ジャンプを ±1〜2 ティック、横移動の向き、狙う点を 0.03〜0.3 ずらす、区間を消す)変えて全体が速くなれば採用し、助走の候補もすべて試します。そのあと、各区間(と 2 区間まとめて)を WS8 の局所探索(`technique`、ティック単位のビーム)で探し直し、返ってくるパレート集合(ティック数と出口の速さ)の各解で置き換えて、後ろを再生し、全体が一番速いものを残します。

**はしご・つた・水**(`Course.linkClimbs`、`ClimbManeuver`): はしご・つた・水のセルをつながったまとまりにして、まとまりに入れる足場(跳んで届くか落ちて入れる、途中に胸の高さの壁がない)から、出られる足場(まとまりの上端からジャンプ 1 回分の高さまで)へ辺を張ります。辺の見積もりは、ジャンプで届かない分の高さを登る速さ(1 ティック 0.1176)で割ったものです。遷移の `ClimbStep` は、入口のセルへ走って跳び、まとまりの中では出口のセルへ向かって登り(押す・泳ぐ)、残りの道のりに比べて高さが足りないときはスニークで落下を止め、出口から足場へ移ります。上に壁や柵が載っていて一部にしか立てないブロックは、立てる部分ごとに別の足場にします(柵の両側が同じ台にならないように)。

**穴・水の階段・スライム・平らなゴール**: 2x2 に並んだ鉄格子・板ガラス・柵の真ん中には、腕の間に体より広い穴が開きます。`Course.linkHoles` がブロックの角と辺の中点で、体の箱が層を通り抜けられ、半ブロック横はどこもふさがっている点を穴として見つけ、周りの台から真下の足場へ辺を張ります。遷移は `HoleManeuver`(`HoleStep`)で、止まる位置が穴の真ん中に来る入力を毎ティック選んで落ちます。水は、体の水を感じる部分(足 +0.4〜+1.4)が同時に触れるセルどうし(上下 1 ブロック空き、斜め)も同じまとまりにし、`ClimbStep` はまとまりの中の最短のセル列をたどって泳ぎます。スライムは跳ね返りの高さが落ちた高さで決まるので、スライムに落ちてこられる足場から、その高さ(+ジャンプ 1 回分)までの足場へ、スライム経由の辺を張ります(`Course.linkBounces`、狙いはスライムの上を通る)。高さのないゴール(min = max)は空中では通れないので、その高さの上面に立つことだけをゴールとみなします。はしごは掛かっている壁へ押して登り、横に流れるときは戻し、上端の天井で止まったらそこから出ます。同じ足場へ行けるはしごが複数あれば、2 本まで試します。

**跳ね返りの高さと、跳ねてまとまりに入る遷移**: 跳ね返りは落ちた高さまでは戻りません(高さ 4 から落ちて 2.55、水の下のスライムに 11 から落ちて 4.3)。`Course.bounceRise` で落下と跳ね返りを鉛直だけ数値計算し、届く高さまでの足場にだけスライム経由の辺を張ります。跳ねる `Step` は 2 段で、跳ねるまではスライムを狙う足場として着地を合わせ、跳ねてから行き先を狙います。跳ね返りで水やはしごのまとまりに届くときは、そのまとまりから出られる足場へも辺を張り(`Course.linkBounceBodies`)、`BounceClimbManeuver`(跳ねる `Step` のあと `ClimbStep`)で実行します。はしごの入口は体の幅で壁を判定し、左右を壁で挟まれた溝の中のはしごへは、開いた側の前を通って入ります。

**制御器が外したときの局所探索**: `ClimbManeuver` の制御器が、狙った足場に 1 つも届かなかったとき(溝の中のはしごへ跳び込むときなど)は、その足場の台への着地を WS8 の局所探索(`technique`、幅 200、1 秒)で探し、見つかった入力列を区間にします。同じ台から同じ台へは、1 回の探索で 2 回までです。`-Dplanner.climbTechnique=0` で切れます。

**助走**(`Runup`): スタートに入るまでは自由(D-003)なので、最初の足場の方向とゴールの方向それぞれに、スタートの手前 0.15〜20 ブロックの点まで歩いて止まり、走る・横移動で走る・連続ジャンプ・走ってスタートに入るティックにジャンプする、の 4 通りでスタートに入ります。スタートに入った最初のティックの状態がすべて A* の根になります(時計は 0)。

スプリントとスニークの切り替えは 3 ティック以上空けます(D-004、`Run.legal`)。スニークは、つたやはしごで落下を止めるときだけ使います。どの解答も最後に判定(`Evaluator`)と `ToggleRule` で確かめます。

## WS8 との取り決め

区間遷移は `Technique.solve(world, entry, ticksSinceLastToggle, Target/Exit, ...)` で受け取り、(ティック数, 出口の速さ)のパレート集合として返してもらいます。入力列は `FixedMove` として計画に入り、再生時に判定の規則で確かめ直します。
