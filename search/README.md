# search

最速タイムを探すモジュールです。問題ごとに、実際に走れる入力列(上界)と、それより速い入力列は無いという証明(下界)を出します。二つが一致すれば、その問題の最速タイムが確定します。

```sh
./gradlew :search:installDist
search/build/install/mctas-search/bin/mctas-search beam problems/v0/03-gap-2.problem.json --width 4000 --out 03.tas
search/build/install/mctas-search/bin/mctas-search bound --cell 0.25 problems/v0/*.problem.json
```

## 上界: `beam`(`exact/Beam.java`)

正確な物理(`physics`)の上で、ティックごとに状態をそろえて進めるビームサーチです。入力は、次の足場の方向を中心に角度を振った「スプリント前進」「前進+左右ストレイフ(視点から45度)」それぞれのジャンプあり・なし、何も押さない、後退です。足場の順序(`exact/Route.java`)は、隙間 4.5 ブロック以下・高さ 1 以下の足場をつないだ最短経路から取ります。スプリントとスニークの切り替えは3ティック以上空けます(README の「サーバーとのずれ」)。見つかるのは走れる入力列で、最適とは限りません。

## 下界: `bound`(`bound/`)

スタート直方体に入ってから k ティック後にありうる状態の集合を、外側から包む集合で追いかけます。k ティック後の集合がゴールに一度も触れなければ、k ティック以内にゴールする入力列はありません。最初に触れた k が下界です。

- 縦方向(`VState`)は、足の高さ・縦速度・接地をビット単位で正確に持ちます。縦の動きは入力からほぼ独立なので、ジャンプする・しない、着地する足場、段差の乗り上げ、スニークの高さ 1.65 と 1.8 で枝分かれさせて、全部を列挙します。
- 横方向(`HState`)は、位置 (x, z)、速度 (vx, vz)、(x, vx)、(z, vz) の4つの凸多角形で持ちます。どの入力でも1ティックの加速は円板に収まるので(地上のスプリント+ジャンプ、空中、スニーク)、全入力をまとめて「円板を足す」操作で扱えます。円板の半径は 1.12.2 の正弦表の誤差 (ROT = 1.0030633、全 float の向きで最大) を含めて外側に取っています。
- ブロックに当たって止まる、スニークで端に止まる、段差に乗り上げる、速度 0.003 未満の切り捨て、の各場合も外側に含めます。天井はまだ扱わず、使う問題は Unsupported で止まります。
- スタートに入る前は時間の制限が無いので、スポーンから不動点まで回します。スタート直方体の面と近くの足場の端で位置を区切り(`--cell` で x 方向を、`--zcell` で z 方向をさらに細かく)、同じ区画の集合だけを合併します。何度も広がる集合は格子に丸めて(widening)止まるようにします。
- スタートに入った瞬間は、直方体の面ごとに、外側から内側へ向かう速度に限って取り出します。その後は k ごとに、同じ縦状態・足場・入った面の集合を `--cap` 個まで持ちます。

扱えるのはフルブロック(滑りやすさ 0.6、変化しないもの)だけで、持ち物のある問題(ブロック設置)はまだ対象外です。

### 健全性の確かめ方

`SoundnessTest` は、正確な物理でランダムな助走と入力の列を走らせ、各ティックの状態が抽象した集合に入っていることを確かめます(03・05・06・07・10、各 300 本)。外側に包めていない箇所があれば、このテストが落ちます。スニーク中の当たり判定の高さの扱いの漏れは、このテストで見つかりました。

下界は `bound --cell 0.25`(cap 16)で、1問 1〜13 分です(02 と 06 は `--cell` なしで同じ値、03 は `--cell 0.1` で 31 分)。差が残る問題では、下界はスタートの横の面(x = -1 や x = 2)から空中で入ってくる状態を許しています。凸多角形の合併で、足場の端から跳んだ状態の位置と速度の相関が失われるためで、区画を細かくすると縮みます(03 は `--cell` なしで 7、0.25 で 8、0.1 で 9)。
