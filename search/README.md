# search

最速タイムを探すモジュールです。問題ごとに、実際に走れる入力列(上界)と、それより速い入力列は無いという証明(下界)を出します。二つが一致すれば、その問題の最速タイムが確定します。

```sh
./gradlew :search:installDist
search/build/install/mctas-search/bin/mctas-search beam problems/v0/03-gap-2.problem.json --width 4000 --out 03.tas
search/build/install/mctas-search/bin/mctas-search bound --cell 0.25 problems/v0/*.problem.json
search/build/install/mctas-search/bin/mctas-search speed problems/v1-full/*.problem.json
```

## 上界: `beam`(`exact/Beam.java`)

正確な物理(`physics`)の上で、ティックごとに状態をそろえて進めるビームサーチです。入力は、次の足場の方向を中心に角度を振った「スプリント前進」「前進+左右ストレイフ(視点から45度)」それぞれのジャンプあり・なし、何も押さない、後退です。足場の順序(`exact/Route.java`)は、隙間 4.5 ブロック以下・高さ 1 以下の足場をつないだ最短経路から取ります。スプリントとスニークの切り替えは3ティック以上空けます(README の「サーバーとのずれ」)。見つかるのは走れる入力列で、最適とは限りません。

## 下界: `bound`(`bound/`)

スタート直方体に入ってから k ティック後にありうる状態の集合を、外側から包む集合で追いかけます。k ティック後の集合がゴールに一度も触れなければ、k ティック以内にゴールする入力列はありません。最初に触れた k が下界です。

- 縦方向(`VState`)は、足の高さ・縦速度・接地をビット単位で正確に持ちます。縦の動きは入力からほぼ独立なので、ジャンプする・しない、着地する足場、段差の乗り上げ、スニークの高さ 1.65 と 1.8 で枝分かれさせて、全部を列挙します。
- 横方向(`HState`)は、位置 (x, z)、速度 (vx, vz)、(x, vx)、(z, vz) の4つの凸多角形で持ちます。どの入力でも1ティックの加速は円板に収まるので(地上のスプリント+ジャンプ、空中、スニーク)、全入力をまとめて「円板を足す」操作で扱えます。円板の半径は 1.12.2 の正弦表の誤差 (ROT = 1.0030633、全 float の向きで最大) を含めて外側に取っています。
- ブロックに当たって止まる、スニークで端に止まる、段差に乗り上げる、速度 0.003 未満の切り捨て、の各場合も外側に含めます。天井はまだ扱わず、使う問題は Unsupported で止まります。
- スタートに入る前は時間の制限が無いので、スポーンから不動点まで回します。スタート直方体の面と近くの足場の端で位置を区切り(`--cell` で x 方向を、`--zcell` で z 方向をさらに細かく)、同じ区画の集合だけを合併します。何度も広がる集合は格子に丸めて(widening)止まるようにします。
- スタートに入った瞬間は、直方体の面ごとに、外側から内側へ向かう速度に限って取り出します。その後は k ごとに、同じ縦状態・足場・入った面の集合を `--cap` 個まで持ちます。

扱えるのはフルブロック(滑りやすさ 0.6、変化しないもの)だけで、持ち物のある問題(ブロック設置)はまだ対象外です。

## どのコースでも出る下界: `speed`(`bound/SpeedBound.java`)

`bound` は扱えるブロックが限られ、大きなコースでは計算が終わりません。`speed` は、スタート直方体からゴールまでの水平距離と高さだけを使う、粗いけれどどのコースでも 1 秒前後で出る下界です。

- 横方向: 1 ティックは「地上(世界にある滑りやすさごと、スプリントジャンプあり・なし)」「空中」「水」「溶岩」のどれかで、どれも速さ |v| のとき最大 |v| + 加速 だけ進み、次の速さは 摩擦 ×(|v| + 加速) 以下です。ブロックへの衝突、はしご、クモの巣、ソウルサンド、0.003 の切り捨てはどれも遅くするだけなので無視します。速さを 1e-4 刻みで持つ動的計画法で、k ティックで進める最大距離を出します。
- ジャンプ後の滞空: ジャンプしたティックは接地で終わらず、着地は下向きに動いているときだけです。そこで、立てる面それぞれについて、周り(空中で届く範囲)の天井と着地面、はしご・クモの巣の効果を全部試してジャンプの弧を追い、着地までの最少ティック数を世界全体で取ります(平地なら 11、頭打ちがあると 1〜2)。近くに液体があればその面は 1 とします。
- 縦方向: スライムが無ければ、足は 1 ティックに 0.6 ブロックより上がりません。
- 状態からの下界 `SpeedBound.ticksFrom(x, 足の y, z, vx, vz)`: 探索の枝刈りや打ち切りに使えます。その状態からゴールに入るまでに要る最少ティック数を返します(状態の速さから同じ表を引くだけなので、1 回の呼び出しは二分探索 1 回)。`prepare(horizon)` で先読みの長さを決めます(既定は問題の上限ティック)。

ブロックの種類によらず健全で、扱えない形も「緩くなるだけ」です。持ち物(ブロック設置)がある問題では、どこにでも氷・スライム・天井が置けるものとして扱います。

### 足場をたどる下界(`bound/HopBound.java`)

走りは、着地(地上に立つ・はしごやつたにつかまる・液体やクモの巣の中)から次の着地までの跳躍の列に分けられます。跳躍は motionY 0.42 以下で始まり(スライムは落ちてきた速さまで)、下りながらしか着地しません。そこで、立てる面(当たり判定の箱の上面を、プレイヤーの半幅 0.3 だけ広げたもの)と、はしご・液体・クモの巣のブロックを頂点にし、跳躍 1 回の最少ティック数を辺の重みにします。

- 水平: 二つの場所の間の距離を `speed` の表で割り当てる
- 登り: 0.6 以下の段は 1 ティック、それより高い段は跳んで頂点の後に乗る弧(近くの天井の下で最短のもの)、液体・クモの巣からは 1 ティック 0.6
- はしご: はしごにいるかは足の位置のブロックで決まるので、はしごの場所はそのブロックそのものを足の高さ 1/8 ずつに切ったものです。さらに、何ティック続けてはしごにいるか(段階)ごとに別の頂点にします。はしごに入るときの上向きの速さは 0.42 以下(届く範囲にスライムがあればその跳ね返りまで)で、空中と同じように減り、壁に押しつけている間は 1 ティック 0.1176 上ります。1 ティックで次の段階へ移り、上りは段階の速さまで、下りは 0.15 まで、横は 0.15 × √2 までです。段差を上るティックは地面で終わるので、はしごの下に着地して段差ではしごに入ることはできません。高さ 6 のはしごを上る走り(64〜69 ティック)の下界は 7 から 44 になりました。
- 下り: その場所で落ちうる最速から落ちる時間
- 届かない跳躍(最も長い跳躍でも距離が足りない)は辺にしない

1.12 の move() は y を先に、x と z を後に動かします。着地のティックの下にある面は、そのティックの初めか終わりの位置の下にあればよいので、着地した状態の位置は面から 1 ティック分はみ出せます。そのため、水平の距離には 1 ティック分の余裕(`far[n+1]`)を持たせ、天井は、跳ぶ場所と着く場所の両方から届く範囲のものだけを使います。着地は、その近くの 0.6 まで低い面に下りて、段差を上って乗ることもできます(近くにそういう面があるときだけ)。落ちるティックが近くのもっと低い面に止められたときも、ティックの初めの足が段の 0.6 下以内なら段差でその段に乗れます。段の上に下りなければ、初めの高さのまま地面になります(浮いた着地)。ただし、y は先に動くので、ティックの初めに箱がその低い面の上にあり、段と同じ高さのブロックに重ならず、段の横まで 1 ティックで届く場所がなければなりません(F-121)。そのため、そういう段からの跳躍は 0.6 下からでもよいとしています(F-119)。また、ジャンプのティックは地上から始まるので、横の 0.6 以下の段に上ることができ、そのときは次のティックで着地します(半ブロックの段の横では、ジャンプ後の最少滞空は 1)。

ゴールから逆向きのダイクストラで、各頂点からゴールまでの最少ティック数を出します。さらに、スタートから時刻の順に、各頂点で着地のティックの終わりにいられる位置の範囲(22.5 度おき 8 方向の上下限で表す 16 角形)を追う前向きの探索をします。跳躍 n ティックで範囲は `far[n]` だけ広がり、次の場所(着地のティックの動きの分だけ広げたもの。地上からの跳躍では、最後の空中のティックの動き)と交わる部分だけが残ります。逆向きでは跳躍ごとに箱の中の移動がただになりますが、前向きでは前の跳躍で着いた位置が引き継がれるので、平らなコースでも強くなります(stpt1 は 48 から 99)。地上の着地からの跳躍は、最初のティックだけが地上で残りは空中なので、前向きの探索では着地のときの速さの上限も持たせ、跳躍ごとにその速さから届く距離と着地の速さを表(`SpeedBound.hops`)で引きます。ジャンプで始められるのは、跳躍の長さがジャンプの範囲に入るときだけです(歩いて落ちる跳躍は加速 0.2 を持たない)。`speed` は、速度の下界・逆向き・前向きのうち最も大きいものを出します。環境変数 `MCTAS_NOFORWARD` で前向きを切れます。

- 区間の下界: `new HopBound(problem, from, to).ticks()` は、`from` の中のどの状態からでも `to` に入るまでの下界です。`new HopBound(problem, from, to, 速さ)` は、地面で終わったティックの状態(速さはそのときの水平の速さの上限)からの下界で、最初のティックは 0.0784 しか落ちず、スライムの上でなければジャンプより速くは上がりません。
- 着地からの下界: `hb.ticksFromGround(x, 足の y, z)` は、その場所に立っている状態(着地した瞬間など)からゴールまでの下界です。表を引くだけなので速く、着地を頂点にする探索(WS9 の A* など)の枝刈りや打ち切りに使えます。`SpeedBound.ticksFrom` と大きい方を取れます。前提は、ポーションなし、ブロックの中に入らないこと(pushOutOfBlocks が起きない)です。
- スタートからの下界: `hb.ticksFromStart(x, 足の y, z)` は、スタート(スタートの箱にいる最後の tick)から、その場所に地面で立つまでの下界です(各頂点の最早到達 tick)。前向き探索のついでに作る表を引くだけです。後ろ向き探索(WS11)で、確かめる着地点の順位付けに使えます。前向き探索はゴールで止まるので、そこまでに届いていない場所はゴールの下界になります。前向き探索が走らないとき(下界 0、ゴールに届かない、設置あり、`MCTAS_NOFORWARD`)は 0 です。
- 区間ごとの差: `mctas-search segments <problem.json> <run.tas> [--length N] [--json out.json]` は、解を約 N ティック(既定 40)ごとの着地で区切り、各区間について、区間の初めの位置と速さから次の区切りの位置(最後はゴール)までの下界と、実際にかかったティック数の差を出します。区間の下界は、その解と同じ点を通る走りに対するものです。差が 0 の区間はもう縮みません。
- 解との差: `mctas-search gap <problem.json> <run.tas>` は解を再生し、各着地での下界と残りのティック数を出します。下界が残りを超えたら `UNSOUND` と出ます。

### 健全性の確かめ方

`SoundnessTest` は、正確な物理でランダムな助走と入力の列を走らせ、各ティックの状態が抽象した集合に入っていることを確かめます(03・05・06・07・10、各 300 本)。外側に包めていない箇所があれば、このテストが落ちます。スニーク中の当たり判定の高さの扱いの漏れは、このテストで見つかりました。

`SpeedBoundTest` は、v0 と v1-dev の全問で、`speed` の下界が既知の解のタイム以下であること、既知の解の各ティックで `ticksFrom` が残りのティック数以下であること、ランダムな入力の列(各問 60 本 × 150 ティック)で、どの区間の水平移動も表の最大距離以下で、ジャンプから着地までが最少滞空以上であることを確かめます。`HopBoundTest` は、既知の解とその途中の区間、ランダムなコース(フルブロック・全形状・液体)上のランダムな走りの区間で、下界が実際にかかったティック数を超えないことを確かめます。
