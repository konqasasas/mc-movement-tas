# 問題集

形式は [../docs/problem-format.md](../docs/problem-format.md) にあります。

## v0(平地とフルブロック、1〜3ジャンプ)

全問、石の1ブロック幅の通路 `x = 0, y = 64, z = -30..0` の端にスポーンし(`(0.5, 65, -29.5)`、南向き)、スタート直方体は通路の先端のブロック `z = 0..1` です。助走は30ブロック分あります。ゴールは着地先ブロックの上面です。

| 問題 | 内容 | 目標(ティック) |
| --- | --- | --- |
| 01-run-10 | 平地を10ブロック先まで | 26 |
| 02-gap-1 | 隙間1(2bジャンプ) | 4 |
| 03-gap-2 | 隙間2(3bジャンプ) | 9 |
| 04-gap-3 | 隙間3(4bジャンプ) | 11 |
| 05-up-1 | 1段上へ、隙間1 | 6 |
| 06-down-1-gap-4 | 1段下へ、隙間4 | 14 |
| 07-side-2 | 斜め前(x+2, z+3)へ | 9 |
| 08-two-jumps | 隙間3、1ブロック足場、隙間2 | 23 |
| 09-three-jumps | 1ブロック足場で隙間2を3回 | 33 |
| 10-three-jumps-zigzag | 足場を左右に振った3連続 | 35 |

目標はすべて `upper_bound` です。簡単なビームサーチ(`mctas-problem search`)で見つけた入力列 `NN-*.tas` が、このティック数でゴールすることを `ProblemSetTest` で確かめています。最適かどうかは未証明で、探索エンジン(M2)が縮めるか、最適と証明するのを待ちます。

## v1: ジャンプコース(5〜12 ジャンプ、いろいろなブロック)

`mctas-approx gen` で作ったランダムなコースです(`approx/README.md`)。v0 と同じ石の通路(`x = 0, y = 64, z = -30..0`)の先端がスタートで、その先に 1×1 か 1×2 の足場が続き、最後の足場への着地がゴールです。足場は高さ −2〜+1、前に 1〜5、横に −2〜+2 ずれ、生成器が「スプリントジャンプで届きそう」と見積もった配置だけを残します(届くかどうかは保証しません)。シード `s` のコースはジャンプ `5 + s % 8` 回で、題名に足場のブロックが順に書いてあります。

| 問題集 | シード | 使い道 |
| --- | --- | --- |
| `v1-dev` | 1〜8 | 探索の調整に使ってよい |
| `v1-holdout` | 1001〜1012 | **成績報告専用**。中身を見て探索を調整しない(調整に使うと成績が実力より良く見えるため) |
| `v1-full` | 2001〜2008 | 足場がすべて石。フルブロックしか扱えない厳密な探索(WS3)で最適値を出し、近似探索の品質を測る正解にする。報告専用 |

足場のブロックは、石、ハーフ(上付き・下付き)、フェンス、丸石の塀、板ガラス、鉄格子、階段(南向き・北向き)、氷、氷塊、ソウルサンド、チェスト、エンチャント台、エンドロッド、頭、金床、トラップドア、日照センサー、シーランタン、カーペットです。ダメージを受けるもの、踏み荒らすもの、跳ねるもの、勝手に変わるものは入れていません。

目標はすべて `upper_bound` で、近似探索 v1 の解答 `sNNNN-*.tas` です(`v1-dev` と `v1-holdout` は 1 問 120 秒、`v1-full` は 30 秒。`ProblemSetTest` で確認)。`v1-holdout` の s1001、s1006、s1009 は解答が見つかっておらず目標がありません(届かないコースかもしれません)。`v1-full` の s2002、s2003、s2005〜s2008 は、WS3 のビームサーチ(`mctas-search beam --width 4000`)のほうが速かったので、その解答に差し替えました(s2003 は新しく目標ができた)。s2004 はどちらも解答がありません。

## human6: 人間の上位記録があるコース(報告専用)

ユーザーが実機で `/mctas export` で書き出した、実在のパルクールコース 6 つです(2026-10-28)。スタート・ゴールの判定とマップは、人間の記録を測ったときと同じです。**成績報告専用**で、中身を見て探索を調整しません(調整には `real` と `v1-dev` を使う)。

目標の種類は `human_benchmark` です。人間の上位プレイヤーの記録で、最適値でも解答のある上界でもないので、解答ファイル(witness)はありません。`mctas-problem score` は、この目標の問題では差のティック数に加えて、記録に対する割合(100% で並ぶ、小さいほど速い)を出します。

| 問題 | 人間の記録(秒) | ティック |
| --- | --- | --- |
| remaining | 15.6 | 312 |
| rampart | 18.9 | 378 |
| poseidon | 18.2 | 364 |
| prism | 28.8 | 576 |
| tohell | 33.7 | 674 |
| verdure | 31.6 | 632 |
