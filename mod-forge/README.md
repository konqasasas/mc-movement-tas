# mctas-recorder(Forge 1.12.2)

実際の Minecraft 1.12.2 でプレイヤーを入力どおりに動かし、毎ティックの状態を記録して、ヘッドレス物理エンジン(`physics`)の予測とビット単位で比べる Mod です。エンジン本体の照合(`oracle`)では確かめられない、クライアント側のキー処理・スプリント判定と、サーバーからの同期の影響を確かめるために使います。

入力を流し込む部分は `InputDriver` に分けてあり、あとで再生用 Mod の土台に使えます。

## 動かし方(Windows)

必要なもの: JDK 21(Gradle 用)。Minecraft 用の JDK 8 はビルド時に自動で取得されます。

```bat
cd C:\mc\mc-movement-tas\mod-forge
gradlew.bat runClient
```

初回は Minecraft と Forge のダウンロードで時間がかかります。起動したら:

1. 新しいワールドを作る: ゲームモードはサバイバル、ワールドタイプはスーパーフラット。
2. ワールドに入ったら、チャットで `/mctas fuzz 100` を実行します(100 本で約 20 分)。実行中は Minecraft を最小化せずに裏に置いたまま、ほかのウィンドウで作業してかまいません。Mod が実行中だけ「フォーカスを失ったらポーズ」を切るので、ゲームは止まらずに進みます(終わると元の設定に戻ります)。Minecraft のウィンドウの中でメニュー・チャット・インベントリを開くと、そのランは INVALID になります。足元の周囲 20 ブロック、高さ 56〜72 の範囲が書き換えられます。
3. 終わるとチャットに結果と記録ファイルの場所が出ます。`mod-forge\run\mctas\logs\` のファイルを送ってください。
4. ハーフブロックや階段などの確認は `/mctas fuzz shapes 100`、水と溶岩の確認は `/mctas fuzz fluids 100`、ボタンを押す確認は `/mctas fuzz press 100` です。

## コマンド

| コマンド | 内容 |
| --- | --- |
| `/mctas fuzz [shapes\|fluids] [本数] [ティック数] [最初のシード]` | エンジンのテストと同じランダムコースを足元に作り、開始位置にテレポートしてランダム入力を流す。既定は 100 本、200 ティック、シード 1。`shapes` を付けると、勝手に変わるもの(砂、作物、感圧板など)を除いた 1.12.2 の全ブロックを使ったコース、`fluids` を付けるとそこに水か溶岩のプールを足したコースになる(水や溶岩はブロック更新なしで置くので、流れ出さない)。`place` を付けると、ホットバーにフルブロックを持たせて右クリックとスロット切り替えを混ぜ、置いたブロックとホットバーの数、サーバーに送った位置まで照合する(実行中はホットバーが書き換わり、終わると元に戻る) |
| `/mctas fuzz press [本数] ...` | ボタンとレバーの付いた柱のあるコースで、右クリックを混ぜる。押したボタンがエンジンの予測どおりの間は押されたままで、その後に戻るかを毎ティック確かめる。ボタンが戻ったティック(押してから何ティック後のティックの初めに戻って見えたか)を記録に書き、終わるとチャットに種類ごとの最小と最大を出す |
| `/mctas probe shulker [回数]` | シュルカーボックスを右クリックして、ふたが開き始めるティック、画面が開くティック、画面を閉じてからふたが閉じ始めるティックを測る(既定 20 回)。上向きの箱に乗って真下を見る回と、東向きの箱の東に立って横を見る回を交互に行い、毎ティックの位置も記録する。足元の 7×7、高さ 4 の範囲が書き換わる。結果はチャットと `mctas/logs/probe-shulker-*.txt` に出る |
| `/mctas script <ファイル>` | `.minecraft/mctas/scripts/<ファイル>` の入力列を今いる場所から流す。1 行 1 ティックで `キー ヨー ピッチ`(キーは W A S D、J=ジャンプ、R=スプリント、N=スニーク、なしは `-`) |
| `/mctas replay <問題> <解> [force]` | 問題ファイルのワールドを問題の座標そのままに作り、スポーン地点にテレポートして解の入力を流す。解は `mctas-solution` の JSON か `.tas` の入力テキスト。パスは絶対パスか `.minecraft/mctas/` からの相対パス。実機でスタートに入ったティックとゴールに入ったティックを、解のファイルに書かれた値・エンジンの予測と並べてチャットと記録に出す。JSON の解の `engineBuild` がこの mod のビルドと違うときは再生しない(mod を解と同じコミットからビルドし直すか、`force` を付ける)。問題に `player.inventory` があるときは、そのホットバーを持たせてから始め、終わると元のホットバーに戻す。このときは、スポーンで位置の定期送信(20 ティックごと)が済んだ瞬間を待ってから始める |
| `/mctas record` | 自分で操作したプレイを記録して照合する。`/mctas stop` で終了 |
| `/mctas stop` | 中断 |
| `/mctas mark from\|to [x y z]` | 問題にする範囲の 2 隅。座標を省くと、照準の先のブロック(届かなければ足元のブロック) |
| `/mctas mark spawn` | 今の位置と向きをスポーンにする(地面に立ち止まって使う) |
| `/mctas mark start x1 y1 z1 x2 y2 z2` | スタート直方体の 2 隅(実数、`~` で自分からの相対) |
| `/mctas mark goal [x y z \| x1 y1 z1 x2 y2 z2]` | ゴール。座標なしか 3 つなら、そのブロック(なしなら照準の先)への着地をゴールにする(問題集の慣習)。6 つなら直方体 |
| `/mctas mark` | 今の印を表示 |
| `/mctas export <名前> [id]` | 印をつけた範囲を `.minecraft/mctas/problems/<名前>.problem.json` に書き出す。範囲の外は空気。未対応ブロック(ポータル類など)や読み込まれていないチャンクがあると書かない |
| `/mctas checkids` | セーブ取り込み(`mctas-problem import`)の数値 ID の表を、このゲームと全 ID・全メタデータで比べ、違いを `.minecraft/mctas/logs/checkids-*.txt` に書く |

## 記録の見方

1 ティック 1 行で、入力と実機の状態(double/float は 16 進で正確に)を書き、最後にエンジンの予測と一致すれば `ok`、違えば `DIFF <項目名>` を書きます。ずれたときはエンジンを実機の状態に合わせ直して続けるので、1 本の中で独立したずれを複数見つけられます。ティックの外で状態が変わったとき(サーバーからのパケットなど)は `# between ticks` として別に記録し、エンジンのずれには数えません。各ランの最後の `# result` 行に MATCH / MISMATCH / INVALID(未対応ブロックに触れた、押してくる動物などが近くにいた、実行中に画面を開いた、またはコースのブロックが走行中に変わった)が出ます。fuzz の間はワールドの `randomTickSpeed` を 0 にして(終わると元に戻ります)、草や作物、雪や氷がコースを変えないようにしています。

ティックの外の変化としてよく出るのは次の 2 つで、どちらもエンジンではなくサーバーとのやり取りによるものです。

- `sprinting`: サーバーはプレイヤーのフラグ(スニーク・スプリント)を約 1 ティック遅れで送り返してきます。スプリントやスニークを短い間に切り替えると、古い値で上書きされることがあります。
- `posX` など位置: サーバーが移動を受け付けず、前の位置に戻した(ブロックにめり込んだ状態から、さらにめり込む方向へ動いたときなど)。

## 解の再生

```
/mctas replay C:/path/to/mc-movement-tas/problems/v0/02-gap-1.problem.json C:/path/to/mc-movement-tas/problems/v0/02-gap-1.tas
```

のように実行すると、問題のブロックとスタート・ゴールを囲む範囲(周り 3 ブロック、上 4 ブロックの余白つき)を空気で消してから問題のワールドを作り、スポーン地点で止まったところから入力を流します。終わるとチャットに次のような行が出ます。

```
real game: FINISHED start 89, goal 93 (4 ticks); solution file: FINISHED start 89, goal 93 (4 ticks); engine: FINISHED start 89, goal 93 (4 ticks)
```

スタート・ゴールの判定は問題ツールの `Judge` そのもの(ティック終了時の位置で判定)を実機の位置に使います。ずれの原因になりうるもの(スポーンにぴったり立てなかった、ダメージを受けた、ブロックが変わった、画面を開いた、動物が近くにいた、エンジンと違ったティック)は続けて注記として出ます。fuzz と違ってダメージは無効にしません(実際のゲームと同じ条件にするため)。ランダムティックは fuzz と同じく実行中だけ止めます。問題のワールドは問題の座標に作るので、スーパーフラットなら地面(y 0〜3)より上にある問題で使ってください。

## ゲーム内で問題を作る

1. 範囲の隅のブロックを見て `/mctas mark from`、反対の隅を見て `/mctas mark to`。
2. スポーンに立って `/mctas mark spawn`。
3. `/mctas mark start ~-1 ~ ~ ~1 ~3 ~1` のようにスタートを、ゴールのブロックを見て `/mctas mark goal`。
4. `/mctas export mycourse` で `.minecraft/mctas/problems/mycourse.problem.json` ができます。同じ場所をセーブから `mctas-problem import` したものと `mctas-problem diffworld` で比べると、取り込みの確認になります。

再生(`/mctas replay`)は問題の周りを空気で消してから作り直すので、元のマップで再生するとその周りが消えます。マップのコピーで再生してください。

## 前提

- オートジャンプは実行中だけ自動で切ります。
- replay・record・fuzz の実行中は、サーバー側で落下ダメージを無効にします(落下ダメージを受けるとサーバーが速度を送り直し、再生がずれるため)。fuzz 中はさらにすべてのダメージを無効にし、満腹度を 20 に戻します。
- クリエイティブでは動きません(飛行の切り替えが入るため)。
