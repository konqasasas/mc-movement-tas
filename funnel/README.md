# funnel: ゴールからの逆向き探索(WS12)

ゴールの側から「ここに立てばゴールまで何ティックで行けるか」を確かめた足場を広げていき、スタートの近くまで届いたら、前向きにその足場をつないで 1 本の解を作る探索です。前向きの A*(WS9 の `planner`)やビーム(WS3b の `approx`)が、ゴールへの道筋を最後まで見通せずに解けない長いコースのために作りました。最適性は保証しません。

```
./gradlew :funnel:installDist
funnel/build/install/mctas-funnel/bin/mctas-funnel solve problems/v1-dev out/ --budget 60
problem/build/install/mctas-problem/bin/mctas-problem time <問題> out/<id>.tas --strict
```

- `solve <問題|フォルダ> <出力フォルダ> [--budget 秒] [--threads N] [--quiet]`: 問題ごとに `--budget` 秒(既定 60)まで探し、`<id の / を _ に>.solution.json` と `.tas` を書きます。`result.search.engine` は `funnel-v4`。
- 環境変数 `FUNNEL_DEBUG=1` で、確かめた足場ごとの結果と、前向きのつなぎの展開を標準出力に出します。前向きに解が見つからなかったときは、一番ゴールに近づいた足場の列と、そこからのビームを出します。`FUNNEL_TRACE=x,y,z` でその足場を確かめるビームの各ティックを、`FUNNEL_TRACE_FWD=N` で前向きの最初の N 回の展開のビームを出します。`FUNNEL_PROBE=x,z0,z1` は、x の列の z0〜z1 のセルの種類と見積もりを高さごとに出します(`FUNNEL_PROBE_FWD=1` で前向きの見積もり)。`FUNNEL_FREE=x0,x1,z0,z1,y` は、足の高さ y で体の箱が入る場所を 1/32 ブロックごとに出します(細い隙間を調べるとき)。`FUNNEL_PATH=x,y,z` は、その点から見積もりの道をセルごとにたどって出します。前向きのつなぎで未確認の足場に見積もりの値で着地する重みは `FUNNEL_GUESS`(既定 1.5、0 で切る)です。

## しくみ

1. **セルの格子**(`Grid`): 足の位置を 0.25 ブロックの格子に置き、高さは 1 ブロックごとの層にします。各セルに、通れる、立てる(上面の高さ)、はしご・つた、水、ジャンプで届く空中、の印を付けます。マグマ・サボテン・炎・溶岩は壁として扱い、マグマの上には立てないものとします。セルの中心では体が入らなくても、セルの中のどこかで入る細い隙間(壁の横の塀の柱、両側の開いたトラップドア)は「隙間のセル」として通れるものとし、体が入る位置を覚えておきます(`Grid.fit`)。隙間のセルを通る動きは見積もりで 2 倍かかるものとし、ほかに道がないときだけ使わせます(壁ぞいに角を切る近道にしないため)。ブロック名の状態(`[facing=...]` など)を外して種類を判定します。
2. **見積もり**(`Field`): 格子の上で、楽観的な動き(平地は 1 ティック 0.33 ブロック、落下、立てるセルからのジャンプ 1.25 まで、はしご・水の上昇、0.6 までの段差)でダイクストラを回します。スタートからの前向きの見積もりと、ゴール(と確かめた足場)へ向かう逆向きの見積もりを作り、逆向きはスタートから届くセルだけを使います(届かない場所を近道にしないため)。空中の状態は、入力なしの放物線が各層を下りながら通るところで、空中制御で届く範囲(ティックとともに広がる)の立てるセルの最小値を取ります(`Landing`)。空中を「浮いている」ように見て、落ちている状態を良く見積もらないためです。
3. **足場の確認**(`Anchors`、`Beam`): ブロックの上面 1 つを 1 つの足場とし、上面の中心に止まって立った状態から、本物の物理のビームで、ゴールか確かめ済みの足場に着地するまで探します。届いたら、その足場の値は「ビームのティック + 着地した足場の値」です。まだ確かめていない足場はビームにとって素通りです。ゴールから近い順(前向きと逆向きの見積もりの和で、確かめ済みの足場から見積もり 30 ティック以内)に、並列で確かめます。止まった状態から跳べない足場(助走のいる 1x1 の足場など)は、スプリントで 0.30 ブロック/ティックで着いた状態と、ほかの足場のビームが実際にそこへ着地した状態(速い順に 6 つ)からも確かめます。失敗した足場は、近く(8 ブロック)の足場が確かめられたら、幅と長さを広げて最大 4 回まで試し直します。
4. **前向きのつなぎ**(`FunnelSolver.assemble`): 確かめた足場がスタートの見積もり 40 ティック以内に届いたら、スポーンから最良優先で、ビーム(幅 150、120 ティック、届かなければ幅 500・240 ティックでもう一度)で確かめ済みの足場への着地を探し、着地した状態(速さも含めて)から次のビームを出します。順位は「経過ティック + 足場の値 × 1.15」(足場の値は止まった状態からなので、着いた速さを残す道では過大になる。同じ通路の見積もりがそろってしまうのを、ゴールに近い方へ少し寄せて崩す)。1 つの足場からの展開は 3 回までです。ゴールに入った列は判定(`Evaluator`)と `ToggleRule` で確かめてから返します。確かめた足場が 1.25 倍 + 10 増えるたびに、つなぎを作り直します。スポーンがスタートの外にあるときは、まず助走だけのビームでスタートの箱に入る状態を集め(入ったあとの見積もりの良い順に 6 つ、位置と速さごとに 1 つ)、それぞれを前向きの探索の根にします(1 本のビームのままでは、そろって跳ねる状態が箱の上を跳び越して、入る状態が残らないことがある)。前向きのビームは、最初に着地を見つけてから 40 ティックで止めます(スタートの箱に入り直すと時計が 0 に戻るので、時計だけでは打ち切れない)。
5. **止まった区間の先へ**(`FunnelSolver.bridge`): スタートへの最短の見積もりが `max(8 秒, 予算/15)` の間 2 ティック以上縮まないか、試す足場がなくなったら、確かめ済みの足場に一番近い、まだ確かめられない足場(と同じ高さで 2.5 ブロック以内の足場)に、見積もり × 1.5 + 10 の仮の値を付けて確かめ済みとして扱い、その手前を確かめ続けます(40 回まで)。仮の足場から出る前向きのビームは幅 500・240 ティックで、その区間を本当に越えなければなりません。

**ビーム**(`Beam`): 各状態で、逆向きの見積もりの次のセルをたどった向きを基準に、0・±20・±45・±90・180 度ずれた向きへ、W・W+A・W+D をスプリントで、ジャンプあり・なしで動かし、ほかに入力なし・ジャンプだけ・スニーク+W・スニークも試します。ただし W+A を 45 度右に向けると W と同じ向きに速く進む(入力の長さが 1 を超えるときだけ 1 にそろえられる)ので、ジャンプしないティックはこの斜めだけ、ジャンプは地面か水の中だけ(W と両方の斜め)にしています。順位は「判定の時計 + 少し先の見積もり」で、同じセル・速度・接地などの状態はまとめ、同じブロックの状態は幅の 1/6 までにします。判定の時計はスタートに最後に入ったティックから数え、それより前(助走)は 0 です。ただし助走の 1 ティックも順位では 0.6 ティックと数えます(スタートの箱を出入りして時計を 0 に戻す状態でビームが埋まらないように)。スプリントとスニークの切り替えは 3 ティック以上空けます(D-004)。
