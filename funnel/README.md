# funnel: ゴールからの逆向き探索(WS12)

ゴールの側から「ここに立てばゴールまで何ティックで行けるか」を確かめた足場を広げていき、スタートの近くまで届いたら、前向きにその足場をつないで 1 本の解を作る探索です。前向きの A*(WS9 の `planner`)やビーム(WS3b の `approx`)が、ゴールへの道筋を最後まで見通せずに解けない長いコースのために作りました。最適性は保証しません。

```
./gradlew :funnel:installDist
funnel/build/install/mctas-funnel/bin/mctas-funnel solve problems/v1-dev out/ --budget 60
problem/build/install/mctas-problem/bin/mctas-problem time <問題> out/<id>.tas --strict
```

- `solve <問題|フォルダ> <出力フォルダ> [--budget 秒] [--threads N] [--quiet]`: 問題ごとに `--budget` 秒(既定 60)まで探し、`<id の / を _ に>.solution.json` と `.tas` を書きます。`result.search.engine` は `funnel-v1`。
- 環境変数 `FUNNEL_DEBUG=1` で、確かめた足場ごとの結果と、前向きのつなぎの展開を標準出力に出します。前向きに解が見つからなかったときは、一番ゴールに近づいた足場の列と、そこからのビームを出します。`FUNNEL_TRACE=x,y,z` でその足場を確かめるビームの各ティックを、`FUNNEL_TRACE_FWD=N` で前向きの最初の N 回の展開のビームを出します。`FUNNEL_PROBE=x,z0,z1` は、x の列の z0〜z1 のセルの種類と見積もりを高さごとに出します。

## しくみ

1. **セルの格子**(`Grid`): 足の位置を 0.25 ブロックの格子に置き、高さは 1 ブロックごとの層にします。各セルに、通れる、立てる(上面の高さ)、はしご・つた、水、ジャンプで届く空中、の印を付けます。マグマ・サボテン・炎・溶岩は壁として扱い、マグマの上には立てないものとします。ブロック名の状態(`[facing=...]` など)を外して種類を判定します。
2. **見積もり**(`Field`): 格子の上で、楽観的な動き(平地は 1 ティック 0.33 ブロック、落下、立てるセルからのジャンプ 1.25 まで、はしご・水の上昇、0.6 までの段差)でダイクストラを回します。スタートからの前向きの見積もりと、ゴール(と確かめた足場)へ向かう逆向きの見積もりを作り、逆向きはスタートから届くセルだけを使います(届かない場所を近道にしないため)。空中の状態は、入力なしの放物線が各層を下りながら通るところで、空中制御で届く範囲(ティックとともに広がる)の立てるセルの最小値を取ります(`Landing`)。空中を「浮いている」ように見て、落ちている状態を良く見積もらないためです。
3. **足場の確認**(`Anchors`、`Beam`): ブロックの上面 1 つを 1 つの足場とし、上面の中心に止まって立った状態から、本物の物理のビームで、ゴールか確かめ済みの足場に着地するまで探します。届いたら、その足場の値は「ビームのティック + 着地した足場の値」です。まだ確かめていない足場はビームにとって素通りです。ゴールから近い順(前向きと逆向きの見積もりの和で、確かめ済みの足場から見積もり 30 ティック以内)に、並列で確かめます。止まった状態から跳べない足場(助走のいる 1x1 の足場など)は、スプリントで 0.30 ブロック/ティックで着いた状態と、ほかの足場のビームが実際にそこへ着地した状態(速い順に 6 つ)からも確かめます。失敗した足場は、近く(8 ブロック)の足場が確かめられたら、幅と長さを広げて最大 4 回まで試し直します。
4. **前向きのつなぎ**(`FunnelSolver.assemble`): 確かめた足場がスタートの見積もり 40 ティック以内に届いたら、スポーンから最良優先で、ビーム(幅 150、120 ティック、届かなければ幅 500・240 ティックでもう一度)で確かめ済みの足場への着地を探し、着地した状態(速さも含めて)から次のビームを出します。順位は「経過ティック + 足場の値 × 1.15」(足場の値は止まった状態からなので、着いた速さを残す道では過大になる。同じ通路の見積もりがそろってしまうのを、ゴールに近い方へ少し寄せて崩す)。1 つの足場からの展開は 3 回までです。ゴールに入った列は判定(`Evaluator`)と `ToggleRule` で確かめてから返します。確かめた足場が 1.25 倍 + 10 増えるたびに、つなぎを作り直します。

**ビーム**(`Beam`): 各状態で、逆向きの見積もりの次のセルをたどった向きを基準に、0・±20・±45・±90・180 度ずれた向きへ、W・W+A・W+D をスプリントで、ジャンプあり・なしで動かし、ほかに入力なし・ジャンプだけ・スニーク+W・スニークも試します。順位は「判定の時計 + 少し先の見積もり」で、同じセル・速度・接地などの状態はまとめ、同じブロックの状態は幅の 1/6 までにします。判定の時計はスタートに最後に入ったティックから数え、それより前(助走)は 0 です。ただし助走の 1 ティックも順位では 0.6 ティックと数えます(スタートの箱を出入りして時計を 0 に戻す状態でビームが埋まらないように)。スプリントとスニークの切り替えは 3 ティック以上空けます(D-004)。
