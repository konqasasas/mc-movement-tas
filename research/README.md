# research/

スレッド(エージェント)どうしは、ここにあるファイルを通して知見を受け渡します。会話の中で分かったことは、ここに書くまで共有されていないものとして扱います。

| ファイル | 中身 | 書き方 |
| --- | --- | --- |
| [lessons/](lessons/) | 作業を始める前に全員が読む教訓 | 自分のワークストリームのファイル(`lessons/<ws>.md`)に追記。古くなった教訓は消さずに「L-xxx で置き換え」と書く |
| [decisions.md](decisions.md) | ルールの裁定と未決の問い | 裁定はユーザーの言葉を出典に。未決の問いは裁定が出たら D 番号を振って移す |
| [findings/](findings/) | 番号付きの知見台帳(測ったこと) | 自分のワークストリームのファイル(`findings/<ws>.md`)に追記のみ。訂正は元の番号を指す新しい項目として書く |
| [experiments/](experiments/) | 実験の登録簿(何をどの条件で走らせたか) | 自分のワークストリームのファイル(`experiments/<ws>.md`)に、走らせる前に登録し、終わったら結果と F 番号を書き足す |
| [handover/](handover/) | 各ワークストリームの引き継ぎメモ | 自分のワークストリームのファイル(`handover/<ws>.md`)だけを上書きしてよい |

### ワークストリームごとのファイル

findings・experiments・lessons・handover は、ワークストリームごとに 1 ファイルです(`ws3.md`、`ws3b.md`、`ws7.md`、`ws8.md`、`ws9.md` など)。複数の PR が同じファイルに追記して、マージのたびに表や番号がぶつかるのを防ぐためです。

- 書くのは自分のワークストリームのファイルだけです。ほかのワークストリームの知見を訂正・補足するときも、自分のファイルに新しい項目を書き、元の番号を指します。
- 番号は下の帯から取るので、ファイルを見れば番号の持ち主が分かります。
- `shared.md` は、帯ルールより前の番号(F-001〜F-099、E-001〜E-099、L-001〜L-099)の置き場です。新しい項目は足しません。
- 新しいワークストリームは、帯を決めてから自分のファイルを作ります。
- 分ける前(2026-10-28)に開いていた PR が `findings.md` などに足した項目は、マージするときに、帯に合うワークストリームのファイルへ移してください。

## 番号の予約帯

並行するスレッドどうしで番号が衝突しないよう、2026-10-28 以降に新しく振る F・E・L・D・Q の番号は、ワークストリームごとの帯から取ります。それより前に main やオープンな PR にあった番号はそのままです。

| ワークストリーム | 帯 |
| --- | --- |
| WS3 厳密探索 | 100 番台(F-101〜) |
| WS3b 近似探索 | 200 番台 |
| WS7 物理高速化 | 300 番台 |
| WS8 局所テクニック | 400 番台 |
| WS9 階層型プランナー | 500 番台 |

帯のないワークストリームが新しくできたら、ここに帯を足してから番号を振ります。

## 作業の前に

1. [lessons/](lessons/) の全ファイルと [decisions.md](decisions.md) を読む。
2. 物理や問題形式を変えたら `./gradlew :problem:writeEngineBuild` でエンジンのビルド ID を更新する(更新し忘れるとテストが落ちる)。解答ファイルにはこの ID が入り、`/mctas replay` と `mctas-problem time --strict` は ID が違う解答を拒否する。

## 結果を「確かめた」と言える条件(5つのゲート)

1. テストが通る(`./gradlew build`)。
2. ビルドが一致する: 解答ファイルの `engineBuild` が、再生・採点するビルドと同じ。
3. 同じ条件で比べる: 同じ問題集、同じ採点コマンド、同じ計算時間の上限。
4. 調整に使っていない問題で確かめる(たくさん試して一番を選ぶと、成績が実力より良く見えるため)。
5. 実機で確かめる(`/mctas replay`)。

どのゲートまで通ったかを findings の項目に書きます。
