# 教訓: WS9 階層型プランナー

作業を始める前に、[shared.md](shared.md) とあわせて全ワークストリームの教訓を読んでください。番号は振り直しません。古くなった教訓は消さずに、新しい項目で置き換えます。


- **L-500 A* が止まったら、一番近づいたノードの後続がどこで捨てられたかを先に見る。** `PLANNER_DEBUG=1` は、後続が「戻りすぎ」「上限超え」「既出・窓の外」のどれで捨てられたかを出す。realdev/ex6 では、後続はすべて動けずに同じ場所に戻っていた(壁)。調整の前に、遷移が動けないのか、見積もりが誤るのか、枝刈りが強すぎるのかを分ける。
- **L-501 楽観的なグラフでも壁は見る。** 壁を無視した辺は、下限として弱いだけでなく、見積もりで探索を壁の前へ誘導して止める(F-503、F-504)。
- **L-502 楽観的な辺は、それを実行する遷移と組にする。** はしごや穴の辺を `StepManeuver` の狙いにも入れると、届かない足場へ走って落ちるだけの枝が増え、狙いの枠を食う。逆に狙いから外すと、入口まで歩く枝がなくなる。辺ごとにどの遷移が実行するかを持たせ(`notByStep`)、遷移の側は台のどこからでも入口へ歩けるようにする(はしごの入口は台単位で探す)。
- **L-503 マージの前に、差分のファイル一覧が自分の持ち場だけかを見る。** PR #53 は、手元で履歴をまとめたときに古い main の木を使ったため、#52 の search/ と ws3 の記録を消す差分を含んだまま、自分でマージしてしまった(#54 で戻した)。main を取り込んだかの確認(`merge-base --is-ancestor`)では、この誤りは見つからない。マージの前に `git diff --stat origin/main...HEAD` で、planner/ と ws9 の記録のほかに触れたファイルがないことを確かめる。
- **L-504 はしごが登れるかは足の中心のセルで決まる。** 体の箱(0.6)がはしごに触れていても、足の位置(`floor(posX), floor(posY), floor(posZ)`)のセルがはしごでなければ登らない(`isOnLadder`)。はしごの遷移やまとまりのつなぎ方を考えるときは、体の箱ではなく足の点が移れるセルで考える(F-515、F-516)。
- **L-505 ほかのジョブの終わりを、名前の文字列で待たない。** ほかのジョブが終わるのを `pgrep -f "<文字列>"` で待つと、待っているシェル自身のコマンド行にその文字列が入っていて、いつまでも終わらない(waza の測定が 30 分遅れた)。待つなら、ジョブを順に並べた 1 つのスクリプトにするか、PID で待つ
