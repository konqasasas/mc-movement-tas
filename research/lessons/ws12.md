# 教訓: WS12 逆向き探索(funnel)

作業を始める前に、[shared.md](shared.md) とあわせて全ワークストリームの教訓を読んでください。番号は振り直しません。古くなった教訓は消さずに、新しい項目で置き換えます。番号は 800 番台です。

- **L-801 ゴールへ向かう見積もりは、スタートから届くセルだけで作る。** 格子の上の楽観的な動きでは、木の上や壁の向こうなど、スタートからは行けない場所を通る近道ができ、その近道の先の足場から確かめ始めて時間を使い切った(waza1 h1)。前向きの見積もりで値の付いたセルに逆向きを限ると、確かめる順がスタートに向かう通路に沿う。
- **L-802 空中の状態は、格子の見積もりではなく、放物線の着地点で見積もる。** 格子の空中セル(ジャンプで届く範囲)を平地と同じに見ると、落ちている状態が「浮いて」ゴールに近づくように見え、ビームが崖から落ちる状態で埋まった。入力なしの放物線が各層を下りるところで、空中制御で届く範囲(ティックとともに広がる)の立てるセルの最小値を取る。届く範囲を大きく取りすぎると同じことが起きる。
- **L-803 ブロックの種類は、名前の状態(`[...]`)を外してから比べる。** はしご・水・マグマを名前の完全一致で探していて、状態つきの名前(`minecraft:ladder[facing=north]`)を見落とし、はしごを壁として扱っていた。
- **L-804 1x1 の足場は、止まった状態からでは確かめられないことがある。** 長い隙間の手前の 1x1 の足場は、前の足場からの速さを持ったまま跳ぶしかない。速さを持った仮の到着状態(スプリントで 0.30)と、ほかの足場のビームが実際にそこへ着地した状態の両方から確かめる。仮の状態だけでは、わずかに届かない跳びが残る。
- **L-805 助走(スタートに入る前)は判定の時計を 0 にするが、ビームの順位では少し数える。** 時計を「スポーンからのティック」にすると、助走の長いコースで、スタートに入る前の状態が最良の着地より遅く見えて刈られる。0 にすると今度は、スタートの箱を出入りして時計を 0 に戻し続ける状態がビームを埋める(v0 05-up-1)。順位では助走の 1 ティックを 0.6 と数える。
- **L-806 スタートに入る前の状態は、足場への着地として数えず、スタートへ向かわせる。** 助走の時計を 0 にしたら、スタートの箱を通らずに足場へ着いた状態が「時計 0 で着いた」として一番良い着地になり、前向きのつなぎ全体がスタートを通らない列になった(waza1 h1)。スタートに入る前は、スタートへの見積もり(×0.6)を順位に足し、着地を記録しない。
- **L-807 助走のある前向きの探索は、助走を先に別のビームで解き、スタートに入った状態を根にする。** 1 本のビームのまま助走させると、同じ手から始まる状態がそろって跳ね、跳躍の頂点でスタートの箱を跳び越して、入った状態が 1 つも残らないことがある(F-806)。根は入ったティックではなく、入った後の見積もりで選ぶ(助走は自由なので、速く入った状態より、良い位置と速さで入った状態が良い)。
- **L-808 格子を楽観的に広げたら、その分の動きは見積もりで高くする。** 体の幅ぎりぎりの隙間を通れるようにしたら、壁ぞいのセルも通れるようになり、見積もりが壁に沿って角を切る道を指して、ビームが追えなくなった(F-807)。見積もりはビームを導くものなので、楽観的すぎると、通れない道へ導く。新しく通れるようにした種類のセルは、ほかに道がないときだけ選ばれる重さにする。
- **L-809 実験中の解析器は、ビルドのたびに上書きされない場所へ写してから走らせる。** 長い実行の途中で `installDist` を走らせると、実行中のプロセスが読む jar が入れ替わり、途中から別の版の結果が混ざる。実行ごとに install を別のフォルダへ写して、そのフォルダの `bin` を使う。
