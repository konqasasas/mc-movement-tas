# 教訓

作業を始める前に全部読んでください。番号は振り直しません。古くなった教訓は消さずに、新しい項目で置き換えます。

## 物理と照合

- **L-001 記憶ではなく公式コードで確かめる。** 1.12.2 の挙動は、覚えている内容と細部が違うことが多い。例: `Block.canPlaceBlockAt` は置く先のブロックの `isReplaceable` ではなく素材の `isReplaceable` を見るので、何層の雪にでも置ける(F-009)。`EntityPlayer.getEyeHeight` はスニーク中でなくても、当たり判定の高さが 1.65 のままなら目の高さが 1.54 になる(F-009)。逆コンパイルしたソースを読み、オラクル(`oracle`、公式 jar のコードを直接動かす)で照合してから信じる。
- **L-002 ランダムな照合は、珍しい並びを引かない。** 近所をランダムに埋めても、ドアの上下の組み合わせや塀の隣のフェンスゲートのような並びはほとんど出ない。周りで形が変わるブロックは、クラス名で列挙して手で扱う(`InteractionTableWriter`)。
- **L-003 サーバー jar にはクライアント専用のメソッドがない。** `Entity.rayTrace` や `ItemBlock.canPlaceBlockOnSide` はサーバー jar から消えている。オラクルではクライアントのコードを写して組み立てる。サーバー側だけの処理(`WorldServer` へのキャストなど)は、オラクルの外から状態を合わせて避ける。
- **L-004 ブロックの選択枠は位置で変わることがある。** 花の選択枠は座標から決まる乱数でずれる(F-010)。当たり判定(衝突箱)と選択枠(視線が当たる箱)は別物。
- **L-005 実機の照合コースには、勝手に変わるブロックを置かない。** 砂、作物、レールなどは、置いた瞬間や時間とともに形が変わり、エンジンのワールドとずれる(F-008)。`BlockType.UNSTABLE` を付けてコースから外す。

## 実機と再生

- **L-006 実機ではサーバーとの往復が状態を書き換える。** スプリント・スニークの切り替えは 3 ティック以上空ける(D-004、F-003)。他のエンティティに押された記録は無効(F-004)。
- **L-007 再生のパスは `.minecraft/mctas` から数える。** 開発環境では `mod-forge/run/client/mctas` なので、リポジトリのファイルは `../../../../problems/...` になる。
- **L-008 mod は解答と同じコミットからビルドする。** mod は `physics` と `problem` のソースを取り込んでビルドするので、古い mod では古い物理で再生される。ビルド ID が違う解答は `/mctas replay` が拒否する。

## ビルドと Git

- **L-009 ソースそのものを読むテストは、入力を宣言する。** Gradle はクラスファイルが変わらない変更(コメントだけなど)でテストを飛ばす。`EngineBuildTest` のようにソースを読むテストは `inputs.dir` を付ける。
- **L-010 `git fetch origin main` だけでは origin/main が更新されないことがある。** `git fetch origin main:refs/remotes/origin/main` と書く。
- **L-011 強制プッシュは使えない。** ブランチを最新にするときは rebase ではなく origin/main をマージする。PR がマージされた後の追加作業は、origin/main から新しいブランチを切る。
