### F-105 v0/05-up-1 の 5 ティックは、実際の物理でもあと 0.0009 ブロック届かない
- 日付: 2026-10-28 / 構成: ブランチ `claude/project-thread-ss9oiz`。助走をスプリントで連続ジャンプし(ジャンプのティックは正面、空中は前進+ストレイフ 45 度)、ジャンプの位相と、最初の 2 ティックの向き(助走の距離を連続的にずらす)を全通り試す総当たり。下界は `bound --cell 0.1`
- 測定: スタートに空中で入ってから 4 ティック後の z は、実際の物理の最良で 1.69909(入る直前の z が -0.0001、ほぼ最良の位相)。5 ティックでゴールするには、着地の前のティックで z > 1.7 が要る(1.12.2 は縦の当たりを先に解くので、着地は前のティックの位置で決まる)。下界の抽象は同じ値を 1.712 まで許すので、下界は 5 にとどまる。加速度の円板の半径を正弦表の誤差の分(ROT = 1.0031)だけ広げるのをやめても(健全でない実験)、05・07・10 の下界は変わらなかった。前進+ストレイフでの z 方向の加速は、全 float の向きで最大 1.0000001 だった
- 結論: 05 の最適はほぼ確実に 6 だが、証明には位置の誤差 0.05% 以下の精度が要る。差の原因は加速度の見積もりではなく、スタート前の状態を区画ごとに 1 つの凸集合に合併していること(助走の履歴の違いをまとめてしまう)。次は、スタート前でも 1 区画に複数の集合を持たせる(`cap` をスタート前にも使う)
- ゲート: 1 / 実験: E-105

### F-106 v0 の 05・07・10 は、下界と上界の差が残ったまま
- 日付: 2026-10-28 / 構成: ブランチ `claude/project-thread-ss9oiz`、`bound --cell 0.1`(05 は 0.05 も)、`beam --width 12000`
- 測定: 下界/上界(ティック): 05 = 5/6、07 = 7/9、10 = 31/33
- 結論: 3 問とも、区画を細かくしても(x で 0.05〜0.1)、加速度の見積もりを詰めても(F-105)下界は変わらない。05 は 5 ティックが実際の物理で 0.0009 ブロック届かない際どい問題で、最適はほぼ確実に 6(F-105)。07 の下界の経路は、スタート直方体の x = 2 の面の外側(足場の外)の空中から入り、そのまま斜めにゴールへ飛ぶもの。足場の端から跳んで x > 2 まで出てから速度を反転させる必要があり、実際には無理と見られる。10 の下界の経路は、左右に振った足場の間で、空中の状態の位置が x 方向に大きく合併されている。どれも、スタート前(10 は途中の足場の間)で、区画ごとに 1 つの凸集合へ合併していることが緩みの原因。次は 1 区画に複数の集合を持たせる表現が要る
- ゲート: 1 / 実験: E-104, E-105

### F-107 どのコースにも健全な下界が出る(速度の上限とジャンプ後の最少滞空)
- 日付: 2026-10-28 / 構成: ブランチ `claude/project-thread-ss9oiz`、`mctas-search speed`(`SpeedBound`)
- 測定: 下界(ティック): realdev ex1 = 131、ex2 = 141、ex3 = 13、ex4(書き出し直し版)= 130、ex5 = 155、ex6 = 236、stpt1 = 132(人間 187)、human6 は poseidon 210、prism 55、rampart 218、remaining 138、tohell 136、verdure 55。1 問 0.1〜2 秒
- 結論: 水平の速さの上限(地上の滑りやすさごと・空中・水・溶岩)と、ジャンプが 2 ティック続けて地上から出られないこと、ジャンプ後の最少滞空から、k ティックで進める最大距離が出る。最少滞空を入れる前(ジャンプを 2 ティックおきに許す)は ex1 = 99、ex6 = 209、poseidon = 186 で、2〜3 割強くなった。実コースはどこかに頭打ち(2 ブロックの高さ)やはしごがあるので最少滞空は 1〜2 で、世界全体の最小を使う限りこれ以上は締まらない。締めるには場所ごとの滞空(経路グラフ側の情報)が要る。stpt1 の差 55 ティックの多くは、高さを稼ぐ区間と頭打ちの無い区間の区別が無いことによる
- ゲート: 1 / 実験: E-106

### F-108 足場をたどる下界で、登るコースの下界が 2.6〜5 倍になった(prism 288、verdure 260、tohell 274)
- 日付: 2026-10-28 / 構成: ブランチ `claude/project-thread-ss9oiz`、`mctas-search speed`(`SpeedBound` と `HopBound` の大きい方)
- 測定: 下界(ティック、括弧内は speed / hops): realdev ex1 = 131(131 / 80)、ex2 = 141(141 / 51)、ex3 = 13(13 / 10)、ex4(書き出し直し版)= 130(130 / 49)、ex5 = 155(155 / 52)、ex6 = 236(236 / 66)、stpt1 = 132(132 / 52、人間 187)。human6(報告のみ、人間の基準タイム): poseidon 210(210 / 60、364)、prism 288(55 / 288、576)、rampart 218(218 / 111、378)、remaining 138(138 / 54、312)、tohell 274(136 / 274、674)、verdure 260(55 / 260、632)。1 問 0.3〜5 秒
- 結論: 走りは、着地(地上・はしご・液体・クモの巣)から次の着地までの跳躍の列に分けられる。跳躍は motionY 0.42 以下で始まり下りながらしか着地しないので、0.6 を超える段は跳んで弧の頂点の後に乗るしかない(高さ 1 の段で 9 ティック、天井があれば短くなる)。この最短経路で、登るコース 3 問の下界が 2.6〜5 倍になった。平らなコースでは、足場を 1 ブロック単位の箱で扱うぶん(箱の中の移動がただになる)速度の下界より弱く、realdev は変わらない。realdev の各方式の解はまだ無いので、最適からの差は解が出たら測る
- ゲート: 1 / 実験: E-107


### F-109 F-108 の prism 288・verdure 260・tohell 274 は健全でなかった(着地は縦を先に解く)
- 日付: 2026-10-28 / 構成: ブランチ `claude/project-thread-ss9oiz`、`mctas-search gap <問題> <解>`(解を再生し、各着地で下界が残りのティック数を超えないか調べる)
- 測定: WS9 の prism の解(595 ティック)の途中で、下界が残りのティック数を超えた。直した後の逆向きの下界は prism 258、verdure 239、tohell 294
- 結論: 1.12 の move() は y を先に、x と z を後に動かすので、着地のティックの終わりの位置は、乗った面から 1 ティック分はみ出せる。F-108 は位置が面の上にあるとして距離を測っていたので強すぎた。水平の距離に 1 ティック分の余裕を持たせ、天井は跳ぶ場所と着く場所の両方から届くものだけを使うように直した。また、着地は弧の頂点より 0.6 まで上の面に段差を上って乗れる(`flag = onGround || d3 != y && d3 < 0`)。F-108 の数値は使わないこと

### F-110 位置の範囲を時刻順に追う前向きの探索で、prism 270・tohell 318、平らなコースの足場の下界も 1.5〜2.6 倍
- 日付: 2026-10-28 / 構成: ブランチ `claude/project-thread-ss9oiz`、`mctas-search speed`(速度・逆向き・前向きの最大)、`mctas-search gap`
- 測定: 下界(ティック、括弧内は 速度 / 足場の列): realdev ex1 = 131(131 / 115)、ex2 = 141(141 / 108)、ex3 = 13(13 / 13)、ex4(書き出し直し版)= 130(130 / 105)、ex5 = 155(155 / 117)、ex6 = 236(236 / 170)、stpt1 = 132(132 / 99)。human6(報告のみ): poseidon 210(210 / 153)、prism 270(55 / 270)、rampart 218(218 / 170)、remaining 138(138 / 106)、tohell 318(136 / 318)、verdure 239(55 / 239)。足場の列の逆向きだけの値は、ex1 61、ex6 64、stpt1 48、rampart 106、prism 258、tohell 294。1 問 5〜32 秒。WS9 の解との差: ex1 488 − 131 = 357、prism 595 − 270 = 325、tohell 734 − 318 = 416。3 本とも、再生した各着地で下界が残りのティック数を超えなかった
- 結論: 逆向きのダイクストラは跳躍ごとに箱の中の移動をただにするが、前向きに位置の範囲(八角形)を引き継ぐと、その分が締まる。登るコース(prism・tohell)は前向きの方が強く、最大になった。平らなコースではまだ速度の下界の方が強い。足場の列の下界は、どの跳躍も最高速から始めてよいとしているので、平らなコースではこれ以上締まりにくい。次に締めるには、跳躍の始めの速さ(助走の有無)を状態に持たせる。WS9 の解と下界の差は 2.0〜3.7 倍で、上界側にも縮める余地がある(prism と tohell は人間の 576・674 の方が速い)

- 測定: 下界(ティック、括弧内は 速度 / 足場の列): realdev ex1 = 131(131 / 124)、ex2 = 141(141 / 129)、ex3 = 13(13 / 13)、ex4(書き出し直し版)= 130(130 / 106)、ex5 = 155(155 / 147)、ex6 = 236(236 / 230)、stpt1 = 132(132 / 129)。human6(報告のみ): poseidon 210(210 / 208)、prism 312(55 / 312)、rampart 218(218 / 209)、remaining 138(138 / 128)、tohell 369(136 / 369)、verdure 244(55 / 244)。1 問 14〜90 秒。WS9・WS10 の解(prism 595・588、tohell 734・727、ex1 488・435)は、どれも下界以上

- ゲート: 1 / 実験: E-109

### F-112 解を区間に分けると、区間ごとの下界の和は全体の下界より大きい(prism 388、tohell 531、ex1 183)

### F-113 着地の余裕を跳躍ごとに絞り、位置の範囲を 16 角形にすると、prism 337・tohell 399・verdure 308
- 日付: 2026-10-28 / 構成: ブランチ `claude/project-thread-ss9oiz`、`mctas-search speed`、`mctas-search segments`
- 測定: 下界(ティック、括弧内は 速度 / 足場の列): human6 prism 337(55 / 337)、tohell 399(136 / 399)、verdure 308(55 / 308)、poseidon 210(210 / 208)、rampart 218(218 / 212)、remaining 138(138 / 128)。realdev ex1 = 131(131 / 124)、ex2 = 141(141 / 130)、ex3 = 13、ex4 = 130(130 / 106)、ex5 = 155(155 / 147)、ex6 = 236(236 / 230)、stpt1 = 132(132 / 130)。1 問 28〜280 秒(8 角形のときの 2〜4 倍)。WS10 の解の区間の下界の和: prism 409 / 588、tohell 561 / 727、ex1 183 / 435。新しく解けた問題の WS9 の解と下界: remaining 328 / 138、ex2 379 / 141、ex5 371 / 155、ex6 453 / 236(どれも解が下界以上)
- 結論: 着地は y を先に解くので、着地のティックの終わりの位置は面から「そのティックの動き」だけはみ出せる。これまでは 1 ティックの最大(ジャンプのティック、約 0.7)を使っていたが、跳躍の最後のティックは空中なので、その跳躍の速さから引いた値(約 0.35)で足りる(prism 312→329)。位置の範囲を 8 方向(16 角形)の上下限にすると、円板で広げるときの角の膨らみが 8% から 2% になる(prism 329→337、tohell 369→399、verdure 244→308)。平らなコースの足場の列は速度の下界にまだ届かない。平らな区間の緩みは位置ではなく、別の所(スタートの扱い、液体・はしごの跳躍は速さを持たない、など)にあると見られる
- ゲート: 1 / 実験: E-111
