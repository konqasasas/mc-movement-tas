# 引き継ぎ: WS11 逆向き探索(2026-10-28)

- **済み**: モジュール `funnel`(`mctas-funnel solve`、funnel/README.md)。0.25 ブロックの格子と楽観的な見積もり(`Grid`、`Field`)、空中の状態の着地の見積もり(`Landing`)、ブロックの上面ごとの足場と、ゴールから外へ本物の物理のビームで確かめる逆向きの探索(`Anchors`、`Beam`、`FunnelSolver.verify`)、スポーンから確かめた足場をつなぐ前向きの最良優先(`FunnelSolver.assemble`)。助走の扱い(L-705、L-706)、細い隙間を通る線に沿う手、スライムの跳ね返りを見積もりに入れる、長いはしごの先の足場も試す。成績は F-701〜F-704
- **解**: `/mnt/project-files/solutions/ws11/`(`time --strict` で確かめたもの)

## 次にやること(優先順。1 つ終えたら次へ)

1. **逆向きの確認が止まる場所を減らす**(F-703): waza1 h4(開いた鉄のトラップドアで 0.625 幅になった戸口と、スライムの穴)、waza2 h3・h4(鉄のドア、シュルカーボックス)、realdev ex1(z 301〜305 の台から z 308 の板と塀へ)。止まった足場の列を `FUNNEL_DEBUG=1` の最後の一覧(スタートからの見積もり順)で見て、`FUNNEL_TRACE=x,y,z` でその足場のビームを追う。見積もり(`Field`)が通れない場所を通れると言っていないか、逆にビームが通れる手を持っていないかを分ける
2. **はしご・水の中にも足場を置く**: 足場はブロックの上面だけなので、長いはしごや水の柱の途中には足場がなく、確かめる距離が長くなる(今は見積もり 30 ティックを超えると、止まったときだけ 60・120・240 と広げる)
3. **前向きのつなぎを速くする**: 1 回の展開(幅 150、120 ティック)に 0.5〜1.5 秒かかり、60 秒では h1 のつなぎが間に合わないことがある。着地した足場の確認済みの入力(`witness`)をまず再生し、だめなときだけビームを出す
4. **ほかの方式との組み合わせ**: 解けた問題の解を WS10 の改善器(`mctas-improve run --seeds`)に渡して縮める。WS3 の `HopBound.ticksFromStart`(PR #64)は、前向きの見積もり(`fwd`)の代わりに使える

- **注意**: waza2(h3〜h5)は開発用、waza3 と human6 と gen-holdout は報告用。調整は v0・v1-dev・realdev・gen-dev・gen-dev2・waza1・waza2 で行う。時間で打ち切る探索なので、同じ問題でも実行ごとに解のティック数と、解けるかどうかが揺れる(waza1 h1 は 60 秒では解けたり解けなかったりする)
