# ルールの裁定と未決の問い

裁定はユーザーが決めたことです。出典(誰がいつ言ったか)を必ず書きます。探索・評価・再生はここに従います。

## 裁定

- **D-001 対象は Minecraft Java Edition 1.12.2、サバイバル。** プロジェクトの前提。
- **D-002 タイムはスタート直方体への最後の侵入からゴールまでのティック数。** スタートとゴールは座標の点で判定する(当たり判定の箱ではない)。定義の全文は [docs/problem-format.md](../docs/problem-format.md) の 2〜3 節。
- **D-003 助走は自由。** スポーンからスタートまでの動きはタイムに入らない。出典: 全体計画(2026-10-27、ユーザー了承)、docs/problem-format.md 3 節。
- **D-004 スプリントとスニークの状態が変わるティックどうしを 3 ティック以上空ける。** 実機ではサーバーが送り返すフラグでスプリント状態が非決定的に上書きされるため(F-003)。壁に当たって自動で切れるスプリントも数える。出典: 実機記録からの制約(README「実機で確認した制約」)。
- **D-005 ダメージを受けるルートは使わない。** サボテン、マグマブロック、炎、溶岩のダメージはエンジンが計算せず、実機ではサーバーが速度を上書きしてずれる。落下ダメージは D-012 で無効にした。出典: docs/problem-format.md 4 節。
- **D-006 他のエンティティに押される記録は無効。** エンジンにはプレイヤー以外のエンティティがない。
- **D-007 ブロックにめり込んだ状態から始めない。** サーバーに位置を戻される(F-005)。
- **D-008 設置するのはフルブロックだけ。** 出典: ユーザー(2026-10-28、全体スレッド「設置するのはフルブロックだけでOK」)。
- **D-009 オフハンドは空。右クリックで作動するブロックは、エンジンが扱うものだけ使う。** 石と木のボタンは押してよく、レバーは右クリックしてよい(クライアントでは何も変わらない)。シュルカーボックスは、開閉のタイミングを実機で測ってから扱う(WS11、F-701〜)。それ以外(チェスト、ドアなど)は使わず、起きたら状態の `unsupportedAction` が立つ。出典: WS2 と WS3 の取り決め(2026-10-28)を、ユーザーの選択で広げた(2026-10-28、WS11 のスレッドで「押す・開けるまで扱う」)。
- **D-010 サーバーが拒否しうる設置は使わない。** クライアントは置けるがサーバーが拒否しうるクリックでは `unsupportedAction` が立つ(F-012)。サーバーがスニークを反映し終えるのは、送ってから 3 ティック以内と仮定する(サーバーが遅れていないこと)。出典: WS2 の実機照合からの制約(2026-10-28)。
- **D-011 低い天井の下でスニークを離さない。** スニークしていないのに高さ 1.65 のままの状態では、サーバーだけが立ち上がって位置を戻すことがある(F-013)。エンジンは `unsupportedAction` を立てる。出典: WS2 の実機照合からの制約(2026-10-28)。
- **D-012 落下ダメージは無効の環境で TAS を評価する。** 落下ダメージを受けると、サーバーが速度を送り直して(`EntityLivingBase.attackEntityFrom` の `markVelocityChanged`)実機の再生がずれる。記録 mod は replay・record・fuzz のすべてで、統合サーバー側の `LivingAttackEvent` で `DamageSource.FALL` を打ち消す。1.12.2 には `fallDamage` のゲームルールがなく、クリエイティブはジャンプの二度押しで飛行に切り替わるので使わない。出典: ユーザー(2026-10-28、全体スレッド「tasの再生層で、落下ダメージを受けてずれる問題があるので落下ダメージオフにしたい」)。
- **D-013 視点を動かさない(向き固定でキーだけ)戦略は、コースによってたまたま使えるだけで、一般の戦略ではない。** stpt1 の人間の記録(約 187 ティック)は視点を一度も動かしていないが、それはこのコースの偶然。探索は視点を自由に使う方式を基本にし、向き固定は研究用の選択肢(`mctas-approx solve --fixed-yaw`、既定オフ)にとどめる。出典: ユーザー(2026-10-28、全体スレッド「向き固定で視点変えてないってのはこのコース限定の戦略っていうことには注意してね」)。
- **D-700 動く仕掛けは、サーバーのワールドとクライアントのワールドを分けて、ティックの順に進める(WS11 の設計)。** エンジンの状態に「サーバー側の変化」(変わったブロック、予約された更新、ブロックイベント)を持たせ、クライアントの 1 ティックごとに、サーバーの 1 ティックを次の順で挟む: (1) クライアントのティック n(右クリック、移動、位置の送信)、(2) サーバーのティック(n で届いたパケットを処理し、予約された更新とブロックイベントを進める)、(3) その結果がクライアントのティック n+1 の初めに届く。統合サーバーでこの順が揺れないことは、シュルカーボックスの 20 回とボタンで確かめた(F-704、F-706)。ずれうるもの(マルチプレイ)は対象外。サーバー側の判定(感圧板、ドア、ピストン)は、エンジンが持つ「サーバーが知っているプレイヤーの位置」(最後に送った位置)で行う。出典: ユーザーの選択(2026-10-28、全体指揮スレッドの決定カード「仕掛けも対応する」)と、それを受けた WS11 の設計。
- **D-701 仕掛けは段階ごとに入れ、段階ごとに PR を分ける。** (1) シュルカーボックスを開ける・閉じる(ふたで押し上げられる。画面が開いている間の入力は空で、閉じる入力を足す)。(2) 感圧板(石・木・重量)とボタンの動力を、サーバーのワールドで進める土台。(3) 動力を受けて開くドア・トラップドア(当たり判定が変わる)。(4) レッドストーンワイヤー・トーチ・リピーター・レッドストーンブロックの動力の伝わり方。(5) ピストン(粘着を含む)が押すブロックとプレイヤー、スライムブロックの跳ね返し。各段階で、オラクル(公式コード)とのランダム照合と、実機での確認(fuzz と目標コースの再生)を通す。目標コースは waza2h4(シュルカー)、waza1h5・waza2h5・waza3h1(感圧板とトラップドア)、waza1h2・waza2h1・waza2h2・waza3h4(ピストン、トーチ、ワイヤー、リピーター、ドア)。waza2h4(右クリックで開けたシュルカーのふたで押し上げる)と waza2h5(木の感圧板で開いた鉄のトラップドアの縁に立つ)は、ユーザーが想定どおりの技だと確認したので正式な目標にする(2026-10-28)。シュルカーの右クリックは TAS の入力(USE)として扱う。出典: 同上(各段階を PR に分けるのは依頼のとおり)。
- **D-702 エンジンが扱わない仕掛けに触れたら `unsupportedAction`。** 段階が入るまでは、その仕掛けが動く条件(感圧板を踏む、動力の変化が届く)で `unsupportedAction` を立て、探索はその状態を捨てる。今の版で立つのは、ボタン・レバーの隣にレッドストーンに反応するブロックがあるときだけ。感圧板を踏んだときの判定は段階 (2) で足す。それまでは、感圧板を踏んだ後の仕掛けの動きをエンジンは知らない。
- **D-500 常に 2 つ以上の根本的に違う探索方式を並行して試し続ける。** 1 つの方式で改善が出ても、ほかの方式を止めずに、違う考え方の探索を少なくとも 2 つ同時に育てる(今は WS3b の近似探索(ビーム+磨き込み)と WS9 の階層型プランナー(足場グラフ+速度状態の A*+つなぎ直し)、ほかに WS3 の厳密探索)。どれも同じ問題集と同じ採点コマンド(`mctas-problem score`)で比べ、勝った方式の考えを他方に移す。出典: ユーザー(2026-10-28、全体スレッド「これで改善とかがあっても、いろんな方法を常に２つ以上試している状態にしたい」)。


- **Q-001 設置できるブロックの種類と数は問題ごとに決めるか。** 今の案: 問題ファイルの `player.inventory` で渡し、渡されたものだけ使える。岩盤のようにサバイバルで手に入らないブロックを許すかも未定。
- **Q-002 成績報告用の問題集をどう分けるか。** 探索の調整に使う問題集とは別に、成績報告だけに使う問題集を用意する方針(全体スレッド、2026-10-28)。中身と置き場所は未定。
- **Q-003 mod の pitch が勝手に下がり続ける現象。** ユーザーが一度見たが再現しなくなった(2026-10-28)。次に起きたら条件を聞く。
